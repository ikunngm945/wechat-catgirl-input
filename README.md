# 微信输入法猫娘模块

在**微信 / QQ** 聊天框里输入到句末标点，自动「喵化」并追加随机颜文字。

   我 → 本喵      你 → 主人      句末加「喵」      末尾追加一个颜文字（190 条）

## 为什么需要这条路线

微信 `com.tencent.mm` **主动屏蔽了无障碍节点树**（实测根节点 `children=0`，
无 FLAG_SECURE，`isAccessibilityTool=true` 仍为空），任何基于无障碍的方案
（含路线 A）都读不到微信输入框。

**但微信对输入法完全透明** —— 输入法本来就看得见用户打的字。
本模块钩在微信输入法进程内，用 `InputConnection` 读写输入框，
因此微信也能用。

## 实测证据

```
CALL onStartInput host=com.tencent.mm
WRITE host=com.tencent.mm ok=true from=[我爱你。] to=[本喵爱主人喵。=^𖥦^=]
```

微信输入框实际显示：`本喵爱主人喵。=^𖥦^=` ✅

## 安装步骤

### 1. 安装模块

从 [Releases](https://github.com/ikunngm945/wechat-catgirl-input-xposed/releases/latest)
下载最新 APK，或直接用已构建好的包：

```sh
pm install -r wechat-catgirl-input-v7.12.apk
```

SHA-256 `7dbd3e4c44f7c1c4e7493041dfb206ecb1f9fe6fabe5f5721bc8e19b20e99dba`

### 2. 在 LSPosed 里启用（必须手动，无法脚本化）

LSPosed 管理器 → **模块** → 「微信输入法猫娘模块」→ 打开开关
→ 作用域**只勾选「微信输入法」**（`com.tencent.wetype`）

> 若列表里看不到本模块，说明 APK 缺少 `assets/xposed_init`。
> 本仓库 build.py 已内置该文件的校验。

### 3. 重启微信输入法

```sh
kill -9 $(pidof com.tencent.wetype)   # 或系统设置里「强行停止」
```
然后点任意输入框让它重新启动。

### 4. 配置白名单

首次运行会自动释放到 `/data/user/0/com.tencent.wetype/qqime/whitelist`：

```
com.tencent.mobileqq
com.tencent.mobileqqi
com.tencent.tim
```

要支持微信就加一行（立即生效，无需重启）：
```sh
/data/adb/QQIME.sh wl add com.tencent.mm
```

## 两个配置文件的规则

- **仅在没有时释放**：已存在的文件一律保留，绝不覆盖你的改动
- **改动即生效**：模块按 `mtime+size` 检测，热重载，不用重启
- 文件为空时回退内置默认值


## 图形配置界面（v2.3+）

配置面板**直接内嵌在微信输入法「关于」页**里（设置 → 关于）：

- **颜文字词库**：显示条数与文件路径
- **白名单**：当前生效的包名（绿色列表）
- **可添加的应用**：列出输入法可见的应用（带图标、名称、包名），
  勾选即加入白名单，取消即移除，**立即生效、无需 root、无需重启**
- **自动发现的应用**：输入法在实际使用中遇到过、但枚举不到的应用，
  会自动记入 `seen` 并显示在这里，同样可勾选加入白名单
- **清空发现记录**：一键清掉 `seen`

### 应用列表的两级来源

| 来源 | 数量（实测） | 说明 |
|---|---|---|
| `queryIntentActivities(ACTION_MAIN+LAUNCHER)` | 31 | 有桌面图标的应用 |
| `queryIntentActivities(ACTION_MAIN)` | **73** | 去掉 category 限制，翻倍 |
| **自动发现（`seen`）** | 动态 | 输入法实际遇到过的，兜底 |

前两级都靠枚举，覆盖不到没有 `MAIN` 入口的应用；
`seen` 是**运行期实测**，输入法碰到哪个 App 的输入框就记下哪个，
因此能兜住枚举遗漏的情况。发现项会与枚举列表去重，不重复显示。

### 为什么输入法能看到应用列表

微信输入法只声明了 4 个 `queriesPackages`，`getInstalledApplications()`
在进程内只能看到 1 个包。但 `queryIntentActivities(LAUNCHER)` 能拿到
**31 个有桌面图标的应用**（实测含微信、QQ），足以覆盖日常聊天场景。

> 若需要更完整的列表，可改用独立 App + `QUERY_ALL_PACKAGES` 声明。

### 实现要点

1. **注入点**：关于页是 `ImeAboutActivity`，跑在**主进程** `com.tencent.wetype`
   （模块已加载在此），因此 UI 可直接写白名单文件，**不需要 root**。
2. **钩法**：钩 `Activity.onCreate` 通用入口，按类名后缀
   `endsWith("ImeAboutActivity")` 匹配。直接 `findAndHookMethod(类名字符串)`
   会失败（`ClassNotFoundError`），因为该类由插件类加载器加载。
3. **时机**：`onCreate` 阶段 `android.R.id.content` 还没有子视图，
   必须用 `decorView.post()` 延迟到消息队列末尾再 `addView`，
   否则日志报"已注入"但界面看不到。
4. **布局**：面板包在限高的 `ScrollView` 里（55% 屏高），避免撑破输入法布局。

### 兼容性

关于页布局由腾讯控制，**输入法更新后布局 id 变化可能导致面板失效**。
届时需重新适配注入点；功能本身（读写在输入法进程内）不受影响。


## 语音输入自动发送（v3.1+）

微信输入法 3.5.4 起，在微信/QQ 里语音转文字后会**自动发送**。
本模块会在发送动作发生前抢先改写文本，保证发出去的就是喵化版。

**实测时序**（定稿到发送只有 5 毫秒）：
```
setComposingText(全文) → finishComposingText → performEditorAction(4)
```

因此拦截点设在 `finishComposingText` 与 `performEditorAction`。

**重要**：语音识别结果常常**不带句末标点**，所以发送前用的是
`transformLoose()`（人称替换 + 颜文字无条件执行），而非打字用的
`transform()`（需检测到标点才动）。详见 [VOICE.md](VOICE.md)。

注意：语音识别期间轮询会主动让路（1.5 秒静默期），
否则会与输入法的流式上屏互相覆盖、造成文本重复。


## 颜文字标签分类（v5.4+）

颜文字支持按**语义标签**分类，根据句子内容自动挑选合适的一类。

### 目录结构

```
/data/user/0/com.tencent.wetype/qqime/
├── katxt              全部颜文字（兜底库，190 条）
├── rules.txt          关键词 → 标签 映射
└── tags/              标签分类目录
    ├── 开心.txt
    ├── 难过.txt
    ├── 饿.txt
    └── ...            想加几个加几个
```

### 规则文件格式

`rules.txt` 一行一条，`关键词=标签`：

```
你好=开心
哈哈=开心
饿了=饿
```

### 匹配逻辑

按句末标点（`。．！？!?；;…`）把文本**切成多句**，每句独立选一个颜文字，
**每句最多一个**：

1. **记忆库完全相同** —— `memory.txt` 里有一样的句子，直接用（不联网）
2. **向量** —— 把句子交给向量模型，在颜文字语义索引里找最贴近的一条。
   要同时满足两个条件才用：① 相似度 ≥ **相似度阈值**（默认 0.42）；
   ② 第一名比第二名高出的分 ≥ **领先间距**（默认 0.015）。
   例外：前两名属于**同一个标签**（同一类心情）时免看间距 ——
   挑哪个都不跑偏，就不必再要求它领先很多
3. **关键词规则** —— `rules.txt` 里句中包含某关键词即命中；
   一句命中多个时取文件里**最后**出现的那个
4. **全库随机** —— 前面都没命中，从 `katxt` 随机

命中之后，这个句子会自动记进 `memory.txt`，下次同样的话就直接命中第 1 级。

**向量问过就算「经过向量」**（v7.7）：即使两个门槛都没过、本次显示回落到了
关键词或随机，只要这句真的送去模型算过，也会把向量**最接近的那条**记进
`memory.txt`（写入值来自向量，不是随机的）。所以同一句话第一次可能随机、
第二次起就按记忆库稳定输出，且不再重复请求模型。
关键词规则与全库随机的结果**不写**记忆库。

### 实测

```
你好。           → 主人好喵。=^𖥦^=          （开心类）
你好。我饿了。    → 主人好喵。⌯'ㅅ'⌯本喵饿了喵。ฅ՞•ﻌ•՞ฅ
                     ↑开心类        ↑饿类
```

### 注意

- 关键词匹配只按**还原人称后**的原文比对（`本喵`→`我`、`主人`→`你`），
  所以「你好=开心」在「你」被替换成「主人」之后依然能命中；
  反过来不会拿替换后的「本喵」去撞规则表，否则「喵」会撞上 `喵=卖萌`。
- `memory.txt` 的键在存与查时都会去掉句末的 `。．；;…`，所以
  「我喜欢你。」与「我喜欢你」是同一条；**但 `？` 与 `！` 会原样保留**，
  「真的吗」「真的吗？」「真的吗！」各存各的。
- 标签文件为空、或标签目录不存在时，自动回退全库随机，不会报错。
- 首次运行会释放 6 个示例标签 + 22 条示例规则，可自行增删改。

## 向量模型匹配（v7.0+）

让模型来判断「这句话配哪个颜文字」，比纯关键词更懂同义改写。

- **接口**：任何 OpenAI 兼容的 `/embeddings`。
  填到 `/v1` 即可（会自动补 `/embeddings`）。实测
  `https://api.siliconflow.cn/v1` + `Qwen/Qwen3-Embedding-0.6B`（维度 1024）。
- **API Key**：存在独立的 `secret.yaml`（权限 0600），**只写不可读** ——
  界面与日志永远不回显内容，只显示「已配置 / 未配置」。
- **两个门槛**：相似度阈值默认 `0.42`，领先间距默认 `0.015`。
  该模型的绝对相似度分布很低（190 条描述彼此高度相似，同一句话的
  最高分常常只有 0.33~0.63，而**错误答案也能到 0.33~0.47**），
  所以单看绝对分分不出「真的贴切」还是「在一堆差不多的里随便挑了一个」。
  46 句实测：
  - 只看绝对分（阈值 0.50）：向量精度 **79%**，全链正确 29/46
  - 绝对分 0.42 + 间距 0.015：向量精度 **93%**，全链正确 31/46
  - 再加「同标签免间距」：向量精度 **90%**，全链正确 **33/46**
  （纯关键词规则是 29/46；向量参与的部分最多，效果最好）
  两个值都能在关于页随时改，无需重装。
- **事前分析**：打字打出句末标点时先请求一次，当场选出颜文字；
  关掉就只做事后分析（打字过程不联网，已记下的句子仍能靠第 1 级命中）。
  事前分析**包含**事后分析。

### 两个文件

| 文件 | 内容 | 用途 |
|---|---|---|
| `memory.txt` | `句子=颜文字`（一行一条） | 第 1 级完全相同比对，按 `mtime+size` 热重载 |
| `kaovec.txt` | `颜文字\t向量` + 头部 `# src= / # model= / # dim=` | 颜文字语义向量索引 |

`memory.txt` 可以直接用文本编辑器改，改完立即生效。
v6.x 的 `vector.txt`（`句子\t颜文字\t向量`）会在首次启动时自动搬迁前两列。
如果两者都没有，首次运行会释放**内置的 577 条常见话术种子**（来自
456 组描述里每条颜文字的「例句」字段，句末 `。．；;…` 已归一），
让「么么哒」「太羞耻了」这类常见话术第一句就走**完全相同命中**
—— 零延迟、零额度。

### 向量索引必须手动重建

索引是**颜文字级**的：把每条颜文字的「语义描述」向量化后存起来。
所以**颜文字改了、或者换了模型，索引就过期了** —— 关于页会显示
「⚠ 颜文字改过了，需重建」，但模块**不会自动重建**（免得白白消耗额度），
要你点一下「重建向量」：

1. 关于页 → 向量面板 → **重建向量** → 确认
2. 190 条约 1~2 秒（按 48 条一批请求），完成后状态栏变「✓ 最新」

没描述的颜文字不进索引，但仍在关键词规则和全库随机里能用。

### 隐私

- `memory.txt` 只存**你自己用过的句子**，不上传。
- 联网只发生在：① 事前分析 / 事后分析时把**当前句子**送去算向量；
  ② 手动重建索引时把**颜文字描述**送去算向量。API Key 只发给配置的接口地址。
- 「记忆库（memory.txt）读写」开关关掉后，第 1 级完全相同比对**不读也不写**，
  检索直接走向量 / 关键词，本轮也不会再往 `memory.txt` 追加。

## LLM 改写（v7.8+）

在关于页打开 **LLM 改写**之后，人称替换与句末后缀交给大模型完成：

- 「文字替换」「句末后缀」两个开关**不再是本地硬替换**，而是作为变量注入提示词
  （`prompt.txt` 里的 `{替换规则}` `{句末后缀}`），由模型自己决定怎么用。
- 默认提示词是**激进风格**（v7.11 起）：**允许扩写**（短句可以扩成两三句、
  加细节加感想），也**允许微调原意**（可以夸张、加善意修饰），
  但仍然守住三条底线：**不把意思改反**（不颠倒立场、不改事实）、
  **疑问句只改语气不替用户回答**、**不许编用户没说过的关键信息**
  （人名 / 时间 / 地点 / 金额 / 承诺）。
- 另有四条防走样约束（都是真机 A/B 试出来后补的）：
  ① **数字 / 金额 / 时间 / 公式 / 英文词 / 链接 / 专有名词原样保留**
  （`10.5` 不许写成「十点五」）；② 句末后缀**每句只在句末用一次**，
  不许塞进词内部（`多少钱` 不能变 `多少喵钱`）；
  ③ 别丢字（`这个多少钱？` 不能改成 `这个要多少喵？`）；
  ④ **任何情况下都要输出内容**，不许返回空白。
- 想要更保守的「贴着原句改」风格，把仓库里的
  [`config/prompt_conservative.txt`](config/prompt_conservative.txt) 覆盖到设备
  `/data/user/0/com.tencent.wetype/qqime/prompt.txt` 即可（激进的默认版是
  [`config/prompt_aggressive.txt`](config/prompt_aggressive.txt)），改完不用重装。
- 改写完的句子再照常逐句匹配颜文字：**开了向量就走向量，没开就直接按规则匹配**。
- 触发时机：**打出句末标点就先改写**（`pre: on`）+ **发送前兜底**再等一小会儿。
- LLM 用的是**完全独立**的一套接口地址 / Key / 模型，与向量那套互不影响。

| 文件 | 内容 |
|---|---|
| `llm.yaml` | `llm` / `pre` / `cache` / `url` / `model` / `temp` / `max` / `max_input` / `think` / `wait` |
| `llm_secret.yaml` | API Key（0600，**只写不可读**） |
| `prompt.txt` | 可编辑提示词，内置 962 字默认值（激进风格） |
| `llm_cache.txt` | 结果缓存，`输入<TAB>输出` 一行一条 |

### 最大输入 / 最大输出 / 思考等级 / 等待（v7.11+）

面板上三个可调项，都只影响**发给模型的请求**，不改变本地回退逻辑：

- **最大输出**（`max`，token，默认 512）：写进请求的 `max_tokens`。
  1 个汉字约 1 token。调大能防长句被截断 —— 目前看到的唯一截断场景是
  **模型把 `max_tokens` 全用在隐藏思考上**（`finish_reason=length` 且正文为空），
  此时日志会明确记成 `LLM 返回空正文 finish=length`，把最大输出调大或把思考等级调低即可。
- **最大输入**（`max_input`，字符，默认 200，`0` = 不限制）：输入超过这个长度
  **直接不改写、回退本地规则**（不做截断），避免超长文本浪费额度。
  触发时日志记 `LLM 跳过：输入 N 字超过上限 M 字`，面板状态栏也会显示原因。
- **思考等级**（`think`）：只做**请求参数透传**，不改写行为。八个档位，
  括号里就是实际下发的值：

  | 界面档位 | 下发内容 |
  |---|---|
  | 默认（不发送） | 不带任何思考字段（兼容性最好） |
  | 关（none） | `reasoning_effort:none` **+** `thinking:{type:disabled}` |
  | 低（low） | `reasoning_effort:low` |
  | 中（medium） | `reasoning_effort:medium` |
  | 高（high） | `reasoning_effort:high` |
  | 极高（xhigh） | `reasoning_effort:xhigh` |
  | 最大（max） | `reasoning_effort:max` |
  | 极限（ultra） | `reasoning_effort:ultra` |

  ⚠ **部分模型可能不支持某些档位，或不支持关闭思考**，请对照所填模型的说明文档。
  这里只是「请求参数」，是否生效由服务端与该模型决定；不支持时服务端可能忽略，
  也可能直接报错（日志记为 `LLM HTTP 400/422`），此时改回「默认」即可。
  实测本机两个模型差异极大：`deepseek-v4-pro` 的档位单调递增（`ultra` 思考约 1005 token），
  而 `deepseek-flash` 只有 `low` / `minimal` 会真的长思考，`medium` / `high` 反而等同关闭。
  高档位务必配合更大的「最大输出」，否则思考会吃满 `max_tokens` 导致空正文。
- **等待**（`wait`，毫秒，默认 2500，范围 200 ~ 15000，v7.12 起）：打字时最多等
  模型多久，超时就用本地规则先发出去。调大能显著减少「这次用了回退、下次才用上
  改写结果」的情况，代价是打字停顿更久。**发送前兜底**另取该值的较小者，
  且最多等 5 秒（`SEND_CAP_MS`），免得按发送键卡住。

### 结果缓存（v7.9）

改写**先查 `llm_cache.txt`**：命中就直接用，不再请求模型；没命中才发给 LLM，
拿到结果后写回这个文件。所以同一句话第二次改写零延迟、零额度。

- 面板上的 **结果缓存** 开关关掉后，这个文件**既不读也不写**
  （内存里已读的也会被丢弃，不会"关了还在用旧缓存"）。
- 面板另有 **清空结果缓存** 按钮。
- 缓存文件可以直接用文本编辑器改，改完立即生效。

## 构建

```sh
python3.12 /root/dsh/qqcat-ime/build.py
```

产物：`dist/QQCatIME-<version>.apk`

### 构建要点（踩过的坑）

1. **必须有 `assets/xposed_init`**，内容为入口类全名
   （`org.dsh.qqcatime.Probe`）。缺它 LSPosed 管理器列表里
   根本看不到模块 —— 这是最初失败的原因。
2. Manifest 需 4 个 meta-data：
   `xposedmodule` / `xposeddescription` / `xposedminversion` / `xposedscope`
3. 配置目录必须在**输入法自己的数据目录**内：输入法跑在
   `untrusted_app` 域，无法写 `/data/adb` 或 `/data/local/tmp`。
4. 改代码后必须重启输入法进程才重新加载。

## 与路线 A 的关系

两条路线并存，互不冲突：

| | 路线 A（无障碍） | 路线 B（本模块） |
|---|---|---|
| 位置 | `/data/adb/QQ/qqcat.sh` | LSPosed 模块 |
| QQ | ✅ | ✅ |
| 微信 | ❌ 被屏蔽 | ✅ |
| 依赖 | 无 | LSPosed 框架 |
| 无障碍注册 | 独占（会临时解绑你的截屏/辅助服务） | 不注册，无影响 |

**微信只能用路线 B；QQ 两条都能用。**

## 已知边界

- 只在**微信输入法**（`com.tencent.wetype`）进程内工作。
  换用搜狗/百度输入法则不生效（可另建同构模块，只需改 scope）。
- 写入后会清 composing 状态，避免触发候选联想。
- 切换 App 时会重置基线，不会误改「输入框里本来就有的旧文本」。
- 不读剪贴板、不发消息。只有**向量模型**会在开启后联网（见下节），
  关掉总开关即完全不请求网络。
