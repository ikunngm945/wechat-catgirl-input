# 微信输入法猫娘模块

在**微信 / QQ** 聊天框里打字，自动「喵化」并追加合适的颜文字。

```
我 → 本喵      你 → 主人      句末加「喵」      末尾追加一个颜文字（190 条）
```

比如输入 `我爱你。`，输入框里就会变成 `本喵爱主人喵。=^𖥦^=`。

它钩在**微信输入法进程内部**，因此微信、QQ 以及任何用微信输入法打字的地方都生效。

---

# 一、功能

## 配置面板

配置面板**直接内嵌在微信输入法「关于」页**里（设置 → 关于），不用另装 App。
所有开关和参数都在这儿改，**改完立即生效**：

| 面板 | 能做什么 |
|---|---|
| **总开关** | 最上面一行，一键停用整个模块（不替换文字、不加后缀颜文字、不联网） |
| **文字替换** | 开关 + 规则表（每行一条 `原词=替换词`） |
| **句末后缀** | 开关 + 后缀内容（默认「喵」） |
| **颜文字** | 开关 + 词库条数与文件路径 |
| **白名单** | 列出输入法可见的应用（带图标、名称、包名），勾选即加入、取消即移除，**立即生效、无需 root、无需重启** |
| **自动发现** | 输入法实际遇到过但枚举不到的应用也会自动记下，同样可勾选 |
| **向量模型** | 接口地址 / 模型 / 相似度阈值 / 领先间距 / 重建索引 |
| **大模型改写** | 接口地址 / 模型 / 温度 / 最大输入输出 / 思考等级 / 等待 / 提示词 / 结果缓存 |
| **复制全部日志** | 遇到问题时一键导出给开发者 |

## 功能汇总

| 功能 | 说明 |
|---|---|
| **人称替换** | `我` → `本喵`，`你` → `主人`（规则表可改） |
| **句末后缀** | 每句末尾加「喵」（内容可改，可整个关掉） |
| **颜文字** | 按句子的意思挑一条追加在末尾，**一句最多一个** |
| **分句** | 按句末标点 `。．！？!?；;…` 切句，每句独立处理 |
| **大模型改写** | 人称替换与句末后缀交给大模型完成，还能扩写句子 |
| **总开关** | 一键停用整个模块 |

颜文字不是随机贴：它按句子的**语义**去挑，共四级，命中哪个用哪个 ——

1. **记忆库完全相同** —— 同一句话以前挑过，直接用（不联网、零延迟）
2. **向量** —— 把句子交给向量模型，在颜文字语义索引里找最贴近的一条
3. **关键词规则** —— `rules.txt` 里句中包含某个关键词就命中对应标签
4. **全库随机** —— 前面都没命中，从 190 条里随机

实测：

```
你好。           → 主人好喵。=^𖥦^=          （开心类）
你好。我饿了。    → 主人好喵。⌯'ㅅ'⌯本喵饿了喵。ฅ՞•ﻌ•՞ฅ
                     ↑开心类        ↑饿类
```

## 大模型改写

打开后，人称替换与句末后缀**交给大模型完成**，还能扩写句子：

```
我在开会，晚点回你。  →  本喵在开会呢，晚点再回主人喵～
你这个菜有点咸了。    →  这道菜有点咸了喵，下次少放点盐啦喵～
```

- 允许扩写（短句扩成两三句、加细节加感想），也允许微调语气
- 但守住三条底线：**不把意思改反**、**疑问句只改语气不替你回答**、
  **不编你没说过的关键信息**（人名 / 时间 / 地点 / 金额 / 承诺）
- 数字 / 公式 / 英文词 / 链接原样保留（`10.5` 不会变成「十点五」）
- 本来要给的「替换规则」「句末后缀」**转换为提示词**注入，由模型自己决定怎么用
- 提示词可编辑，也内置了默认值

改写完的句子再照常逐句匹配颜文字：**开了向量就走向量，没开就直接按规则匹配**。

## 隐私

- 不读剪贴板、不发消息、不注册无障碍服务。
- 联网只发生在：① 开启向量后把**当前句子**送去算向量；
  ② 手动重建索引时把**颜文字描述**送去算向量；③ 开启大模型改写后把**当前句子**送模型。
- `memory.txt` 只存你自己用过的句子，不上传。
- API Key 存在独立文件里（权限 0600，**只写不可读**），界面与日志永远只显示「已配置 / 未配置」。
- 关掉总开关即完全不请求网络。

# 二、安装与使用

从 [Releases](https://github.com/ikunngm945/wechat-catgirl-input-xposed/releases/latest)
下载模块，在 LSPosed 内启用，然后重启微信输入法。

## 配置白名单

首次运行会自动释放到 `/data/user/0/com.tencent.wetype/qqime/whitelist`：

```
com.tencent.mobileqq
com.tencent.mobileqqi
com.tencent.tim
```

要支持微信，在关于页的**白名单**里勾选「微信」即可（立即生效，无需 root、无需重启）。

## 三种触发方式（满足任一种就改写）

1. **打出句末标点**：输入到 `。！？…` 等标点后稍等，自动改写
2. **输入法发送键**：点微信输入法的「发送」按钮时触发
3. **语音转文字**：说完自动发送前改写（语音识别结果常常不带句末标点，
   这条路径用的是宽松模式 —— 人称替换与颜文字无条件执行）

> 微信 / QQ 需先开启：设置 → 辅助输入 → 回车键发送。

# 三、设置说明

## 总开关

关于页最上面那一行。关掉后整个模块不生效：不替换文字、不加后缀与颜文字，
也不请求大模型与向量。

只是不想用大模型的话，关掉「大模型改写」就够了，不必动总开关。

## 文字替换与句末后缀

- **文字替换规则**：每行一条 `原词=替换词`。行首加 `!` 可单独关闭该条，例如 `!你=主人`。
- **句末后缀**：默认「喵」，可改成任意内容；「启用句末后缀」开关可整个关掉。
- **启用颜文字**：关掉就只加后缀、不追加颜文字。
- **对所有应用生效**：打开则全应用生效；关闭则只按下面的白名单。

## 颜文字标签分类

颜文字可按**语义标签**分类，按句子内容自动挑选合适的一类。

```
/data/user/0/com.tencent.wetype/qqime/
├── katxt              全部颜文字（兜底库，190 条）
├── rules.txt          关键词 → 标签 映射
└── tags/              标签分类目录
    ├── 开心.txt
    ├── 难过.txt
    ├── 饿.txt
    └── ...            想加几个加几个
```

`rules.txt` 一行一条，`关键词=标签`：

```
你好=开心
哈哈=开心
饿了=饿
```

匹配逻辑见上文「文字喵化」的四级顺序。命中之后这个句子会自动记进
`memory.txt`，下次同样的话就直接命中第 1 级。

**向量问过就算「经过向量」**：即使两个门槛都没过、本次显示回落到了关键词或随机，
只要这句真的送去模型算过，也会把向量**最接近的那条**记进 `memory.txt`
（写入值来自向量，不是随机的）。所以同一句话第一次可能随机、第二次起就按记忆库
稳定输出，且不再重复请求模型。关键词规则与全库随机的结果**不写**记忆库。

### 注意

- 关键词匹配只按**还原人称后**的原文比对（`本喵`→`我`、`主人`→`你`），
  所以「你好=开心」在「你」被替换成「主人」之后依然能命中；
  反过来不会拿替换后的「本喵」去撞规则表，否则「喵」会撞上 `喵=卖萌`。
- `memory.txt` 的键在存与查时都会去掉句末的 `。．；;…`，所以
  「我喜欢你。」与「我喜欢你」是同一条；**但 `？` 与 `！` 会原样保留**，
  「真的吗」「真的吗？」「真的吗！」各存各的。
- 标签文件为空、或标签目录不存在时，自动回退全库随机，不会报错。
- 首次运行会释放 6 个示例标签 + 22 条示例规则，可自行增删改。
- 词库文件 `katxt` 一行一个颜文字，改完立即生效，无需重启。

## 向量模型

让模型来判断「这句话配哪个颜文字」，比纯关键词更懂同义改写。

- **接口**：任何 OpenAI 兼容的 `/embeddings`。填到 `/v1` 即可（会自动补 `/embeddings`）。
  实测 `https://api.siliconflow.cn/v1` + `Qwen/Qwen3-Embedding-0.6B`（维度 1024）。
- **两个门槛**：相似度阈值默认 `0.42`，领先间距默认 `0.015`。
  该模型的绝对相似度分布很低（190 条描述彼此高度相似，同一句话的最高分常常只有
  0.33~0.63，而**错误答案也能到 0.33~0.47**），所以单看绝对分分不出「真的贴切」
  还是「在一堆差不多的里随便挑了一个」。46 句实测：

  | 策略 | 向量精度 | 全链正确 |
  |---|---|---|
  | 只看绝对分（阈值 0.50） | 79% | 29/46 |
  | 绝对分 0.42 + 间距 0.015 | 93% | 31/46 |
  | 再加「同标签免间距」 | 90% | **33/46** |

  （纯关键词规则是 29/46。）两个值都能在关于页随时改，无需重装。
- **同标签免间距**：前两名属于**同一个标签**（同一类心情）时免看间距 ——
  挑哪个都不跑偏，就不必再要求它领先很多。
- **事前分析**：打字打出句末标点时先请求一次，当场选出颜文字；
  关掉就只做事后分析（打字过程不联网，已记下的句子仍能靠第 1 级命中）。
  事前分析**包含**事后分析。

### 两个文件

| 文件 | 内容 | 用途 |
|---|---|---|
| `memory.txt` | `句子=颜文字`（一行一条） | 第 1 级完全相同比对，按 `mtime+size` 热重载 |
| `kaovec.txt` | `颜文字\t向量` + 头部 `# src= / # model= / # dim=` | 颜文字语义向量索引 |

`memory.txt` 可以直接用文本编辑器改，改完立即生效。
如果两者都没有，首次运行会释放**内置的常见话术种子**，让「么么哒」「太羞耻了」
这类常见话术第一句就走**完全相同命中** —— 零延迟、零额度。

### 向量索引必须手动重建

索引是**颜文字级**的：把每条颜文字的「语义描述」向量化后存起来。
所以**颜文字改了、或者换了模型，索引就过期了** —— 关于页会显示
「⚠ 颜文字改过了，需重建」，但模块**不会自动重建**（免得白白消耗额度），
要你点一下「重建向量」：

1. 关于页 → 向量面板 → **重建向量** → 确认
2. 190 条约 1~2 秒（按 48 条一批请求），完成后状态栏变「✓ 最新」

没描述的颜文字不进索引，但仍在关键词规则和全库随机里能用。

### 记忆库开关

面板上的「记忆库（`memory.txt`）读写」开关关掉后，第 1 级完全相同比对
**不读也不写**，检索直接走向量 / 关键词，本轮也不会再往 `memory.txt` 追加。

## 大模型改写

在关于页打开后，人称替换与句末后缀交给大模型完成。用的是**完全独立**的一套
接口地址 / Key / 模型，与向量那套互不影响。

### 改写失败会写明原因

接口报错、请求超时、没网、必填项没配，都**不会静默回退**，而是把原因直接
追加在原文后面，例如：

```
你好。⚠ LLM 改写失败：等待超时（2500 毫秒内没返回结果）
```

- 失败提示**不带零宽标记**，所以它不会被当成「已改写」的内容，下一轮会被
  自动摘掉、按最新状态重新判断。
- 触发原因：`LLM HTTP 401`、`等待超时（N 毫秒内没返回结果）`、
  `未配置接口地址 / 模型 / Key`、`异常 UnknownHostException`（没网）、
  `返回正文为空（length）`、`返回不合规 输出超长（…）`。
- 超长输入仍按「最大输入」直接跳过并写明原因。

### 改写过的句子带零宽标记

模型改写成功的段落会被一对**零宽字符**（U+200B）包起来，例如
`\u200B主人好呀喵～\u200B`。聊天窗口里肉眼完全看不见，但模块下次读到就知道
**这段已经改写过，原样放行**：

- 用户接着往后打字时，只有新打的那段会被处理，已改写的旧段不会反复送模型。
- 送去模型 / 匹配向量前会先把零宽字符剥掉，不会污染输入。
- 两个零宽字符是**成对**的。如果用户退格删掉了其中一个，标记就「落单」了，
  模块会认为这段文字被用户动过，**清掉标记整段重来** ——
  绝不会因为少了一个零宽就让这段话（以及后面新打的字）永远改不了。
- **还按内容认一遍**：实测有些宿主机（如微信输入法写回 QQ 输入框时）
  会**吃掉行尾那个零宽**，于是下一轮读到的是「看着像自由文字、其实已经改写过」
  的文本。只按标记判断的话，早就改好的旧段会被**整段重新送模型**
  （真机实测多花 4.2 秒，还把已改好的话又改了一遍）。现在模块会把模型产出过的
  正文记在内存里，读到自由文字时按内容比对最长匹配：
  - 整段就是旧输出 → 原样返回，**不补回标记**（宿主若每次都吃行尾零宽，
    补一次吃一次会变成「写回 → 被吃 → 再写回」死循环，内容比对足以认出它）。
  - 旧输出夹在自由文字**中间**（接着打字时很常见）→ 只保护那一段，
    真正的新文字才送模型。
  - 少于 6 个字符的输出（「喵」这类）不参与比对，避免误伤用户原文。

### 提示词

- 「文字替换」「句末后缀」两个开关**不再是本地硬替换**，而是作为变量注入提示词
  （`prompt.txt` 里的 `{替换规则}` `{句末后缀}`），由模型自己决定怎么用。
- 默认提示词是**激进风格**：**允许扩写**（短句可以扩成两三句、加细节加感想），
  也**允许微调原意**（可以夸张、加善意修饰），但仍然守住三条底线：
  **不把意思改反**（不颠倒立场、不改事实）、**疑问句只改语气不替用户回答**、
  **不许编用户没说过的关键信息**（人名 / 时间 / 地点 / 金额 / 承诺）。
- 另有四条防走样约束（都是真机 A/B 试出来后补的）：
  ① **数字 / 金额 / 时间 / 公式 / 英文词 / 链接 / 专有名词原样保留**
  （`10.5` 不许写成「十点五」）；② 句末后缀**每句只在句末用一次**，
  不许塞进词内部（`多少钱` 不能变 `多少喵钱`）；
  ③ 别丢字（`这个多少钱？` 不能改成 `这个要多少喵？`）；
  ④ **任何情况下都要输出内容**，不许返回空白。
- 提示词开头即声明「你的唯一工作是**改写**用户发来的话，不是和用户对话」
  「**绝对不要回复内容**」，并给出**正反例**（输入「我喜欢你」→ 允许
  「本喵也超喜欢主人呀…」这类**对台词的改写**，**绝不允许**「谢谢你」
  「我也喜欢你」这类**针对用户的回应**）；规则末尾再自查一遍。
  修掉了模型偶尔**回复用户**而不是**改写这句话**的毛病。
- 想要更保守的「贴着原句改」风格，把仓库里的
  [`config/prompt_conservative.txt`](config/prompt_conservative.txt) 覆盖到设备
  `/data/user/0/com.tencent.wetype/qqime/prompt.txt` 即可（激进的默认版是
  [`config/prompt_aggressive.txt`](config/prompt_aggressive.txt)），改完不用重装。

### 最大输入 / 最大输出 / 思考等级 / 等待

面板上四个可调项：

- **最大输出**（`max`，token，默认 512）：写进请求的 `max_tokens`。
  1 个汉字约 1 token。调大能防长句被截断 —— 目前看到的唯一截断场景是
  **模型把 `max_tokens` 全用在隐藏思考上**（`finish_reason=length` 且正文为空），
  此时日志会明确记成 `LLM 返回空正文 finish=length`，把最大输出调大或把思考
  等级调低即可。
- **最大输入**（`max_input`，字符，默认 200，`0` = 不限制）：输入超过这个长度
  **直接不改写**（不做截断），避免超长文本浪费额度。触发时日志记
  `LLM 跳过：输入 N 字超过上限 M 字`，面板状态栏也会显示原因。
- **思考等级**（`think`）：只做**请求参数透传**，不改写行为。八个档位，
  括号里就是实际下发的值：

  | 界面档位 | 下发内容 |
  |---|---|
  | 默认（不发送） | 不带任何思考字段（兼容性最好） |
  | 关（none） | `reasoning_effort:none` **+** `thinking:{type:disabled}` |
  | 低（low） | `reasoning_effort:low` |
  | 中（medium） | `reasoning_effort:medium` |
  | 高（high） | `reasoning_effort:high` |
  | 极高（xhigh） | `reasoning_effort:xhigh` |
  | 最大（max） | `reasoning_effort:max` |
  | 极限（ultra） | `reasoning_effort:ultra` |

  ⚠ **部分模型可能不支持某些档位，或不支持关闭思考**，请对照所填模型的说明文档。
  这里只是「请求参数」，是否生效由服务端与该模型决定；不支持时服务端可能忽略，
  也可能直接报错（日志记为 `LLM HTTP 400/422`），此时改回「默认」即可。
  实测本机两个模型差异极大：`deepseek-v4-pro` 的档位单调递增（`ultra` 思考约
  1005 token），而 `deepseek-flash` 只有 `low` / `minimal` 会真的长思考，
  `medium` / `high` 反而等同关闭。高档位务必配合更大的「最大输出」，
  否则思考会吃满 `max_tokens` 导致空正文。
- **等待**（`wait`，毫秒，默认 2500，范围 200 ~ 15000）：打字时最多等模型多久，
  超时就把失败原因追加在原文后面。调大能显著减少「等不到结果」的情况，
  代价是打字停顿更久。填多少就等多少，**不封顶**（发送前兜底同样按这个时长）。

### 结果缓存

改写**先查 `llm_cache.txt`**：命中就直接用，不再请求模型；没命中才发给模型，
拿到结果后写回这个文件。所以同一句话第二次改写零延迟、零额度。

- 面板上的 **结果缓存** 开关关掉后，这个文件**既不读也不写**
  （内存里已读的也会被丢弃，不会「关了还在用旧缓存」）。
- 面板另有 **清空结果缓存** 按钮。
- 缓存文件可以直接用文本编辑器改，改完立即生效。

### 四个文件

| 文件 | 内容 |
|---|---|
| `llm.yaml` | `llm` / `pre` / `cache` / `url` / `model` / `temp` / `max` / `max_input` / `think` / `wait` |
| `llm_secret.yaml` | API Key（0600，**只写不可读**） |
| `prompt.txt` | 可编辑提示词，内置激进风格默认值 |
| `llm_cache.txt` | 结果缓存，`输入<TAB>输出` 一行一条 |

## 配置文件的通用规则

- **仅在没有时释放**：已存在的文件一律保留，绝不覆盖你的改动
- **改动即生效**：模块按 `mtime+size` 检测，热重载，不用重启
- 文件为空时回退内置默认值

# 四、实现原理


## 进程结构（关键）

输入法有**两个进程**：

| 进程 | 职责 |
|---|---|
| `com.tencent.wetype` | 主进程，只承载「关于」页 UI（模块的配置面板在这里） |
| `com.tencent.wetype:hld` | **轮询循环与发送钩子都在这里** |

`pidof com.tencent.wetype` 只返回主进程 PID，所以重启时必须
**两个都杀**（`kill -9 $(pidof ...)` 杀不干净，`:hld` 还活着就还是旧代码）。

## 钩子与触发时机

钩的目标是 `android.inputmethodservice.RemoteInputConnection`，
通过 afterHook `getCurrentInputConnection()` 动态发现。

语音路径的时序（定稿到发送只有 5 毫秒）：

```
setComposingText(全文) → finishComposingText → performEditorAction(4)
```

因此拦截点设在 `finishComposingText` 与 `performEditorAction`。

语音识别结果常常**不带句末标点**，所以发送前用的是 `transformLoose()`
（人称替换 + 颜文字无条件执行），而非打字用的 `transform()`（需检测到标点才动）。
详见 [VOICE.md](VOICE.md)。

注意：语音识别期间轮询会主动让路（1.5 秒静默期），
否则会与输入法的流式上屏互相覆盖、造成文本重复。

## 为什么输入法能看到应用列表

微信输入法只声明了 4 个 `queriesPackages`，`getInstalledApplications()`
在进程内只能看到 1 个包。但 `queryIntentActivities(LAUNCHER)` 能拿到
**31 个有桌面图标的应用**（实测含微信、QQ），足以覆盖日常聊天场景。

| 来源 | 数量（实测） | 说明 |
|---|---|---|
| `queryIntentActivities(ACTION_MAIN+LAUNCHER)` | 31 | 有桌面图标的应用 |
| `queryIntentActivities(ACTION_MAIN)` | **73** | 去掉 category 限制，翻倍 |
| **自动发现（`seen`）** | 动态 | 输入法实际遇到过的，兜底 |

前两级都靠枚举，覆盖不到没有 `MAIN` 入口的应用；`seen` 是**运行期实测**，
输入法碰到哪个 App 的输入框就记下哪个。发现项会与枚举列表去重。

> 若需要更完整的列表，可改用独立 App + `QUERY_ALL_PACKAGES` 声明。

## 配置面板的注入要点

1. **注入点**：关于页是 `ImeAboutActivity`，跑在**主进程** `com.tencent.wetype`
   （模块已加载在此），因此 UI 可直接写白名单文件，**不需要 root**。
2. **钩法**：钩 `Activity.onCreate` 通用入口，按类名后缀
   `endsWith("ImeAboutActivity")` 匹配。直接 `findAndHookMethod(类名字符串)`
   会失败（`ClassNotFoundError`），因为该类由插件类加载器加载。
3. **时机**：`onCreate` 阶段 `android.R.id.content` 还没有子视图，
   必须用 `decorView.post()` 延迟到消息队列末尾再 `addView`，
   否则日志报「已注入」但界面看不到。
4. **布局**：面板包在限高的 `ScrollView` 里（55% 屏高），避免撑破输入法布局。

**兼容性**：关于页布局由腾讯控制，**输入法更新后布局 id 变化可能导致面板失效**。
届时需重新适配注入点；功能本身（读写在输入法进程内）不受影响。



# 五、已知边界

- 只在**微信输入法**（`com.tencent.wetype`）进程内工作。
  换用搜狗/百度输入法则不生效（可另建同构模块，只需改 scope）。
- 写入后会清 composing 状态，避免触发候选联想。
- 切换 App 时会重置基线，不会误改「输入框里本来就有的旧文本」。
- 大模型产出过的正文只记在**内存**里，输入法进程重启后认不回残留的旧文字，
  会重新送一次模型；写回一次补上标记就恢复正常。
- 不读剪贴板、不发消息。只有**向量模型**与**大模型改写**会在开启后联网，
  关掉总开关即完全不请求网络。
